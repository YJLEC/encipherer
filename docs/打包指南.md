# Encipherer 打包指南

面向需要**自行打包/分发**的用户或维护者。三种分发形态的打包方式各不相同:

| 分发物 | 打包方式 | 在哪台机器上做 |
|---|---|---|
| 单文件版 `Encipherer.html` | `npm run build` | 任意系统(Node ≥ 18) |
| Windows 便携版 / 安装包 | `npm run dist:win` | **Windows** 本机 |
| macOS / Linux 桌面版 | `npm run dist:mac` / `npm run dist:linux` | **对应目标系统**本机 |

---

## 0. 前置条件(所有平台)

```bash
npm install        # 安装 devDependencies:electron 33 + electron-builder 25
```

- Node.js ≥ 18(本项目用 Node 24 验证);
- 首次打包需要**联网**:electron-builder 会下载 Electron 运行时与各平台的打包资源(如 Windows 的 NSIS);下载完成后即完全离线;
- Windows 下建议使用 Git Bash / PowerShell 执行命令。

## 1. 单文件版(最简单的分发)

```bash
npm run build
```

产物:**`dist/Encipherer.html`**(约 2.1 MB)。

分发方式就是**复制这一个文件**——发给对方、放 U 盘、挂内网共享都行。它内嵌了全部 JS/CSS 与第三方库(SheetJS、ExcelJS),双击用浏览器打开即用,无需安装任何东西。

重新打包时机:`src/`、`vendor/` 或版本号(`package.json` 的 `version`)有任何改动之后。构建脚本(`build/build.js`)会把版本与构建时间写进文件内(帮助页可见)。

## 2. Windows 桌面版(便携版 + 安装包)

在 **Windows** 机器上:

```bash
npm run build                      # 先确保 dist/Encipherer.html 是最新
npm run dist:win -- --publish never
```

产物输出在 **`release/`** 目录(此目录已被 gitignore):

| 文件 | 说明 | 体积(1.0.0 实测) |
|---|---|---|
| `Encipherer-便携版-1.0.0.exe` | 单文件绿色版,双击即用、免安装,适合 U 盘携带 | 71.2 MB |
| `Encipherer-安装包-1.0.0.exe` | NSIS 安装器,可选安装目录、建桌面快捷方式 | 71.4 MB |
| `Encipherer-安装包-1.0.0.exe.blockmap` | 安装包的块映射(增量更新用,可不分发) | 78 KB |
| `win-unpacked/` | 解包目录,内含完整应用文件(调试用,不必分发) | 约 271 MB(磁盘占用) |

> 体积主要来自 Electron 运行时(Chromium),71 MB 左右属 Electron 应用正常水平。

说明:

- 打包配置在 `package.json` 的 `build` 段:appId `com.encipherer.app`,productName `Encipherer`,只打包 `electron/**`、`dist/Encipherer.html` 与 `package.json`——应用本体就是内嵌的单文件 HTML;
- 桌面壳(`electron/main.js`)以 `app://` 特权协议加载内嵌页面,存储(IndexedDB/localStorage)不受浏览器 `file://` 限制,且阻断一切外部导航;
- `--publish never` 表示只本地打包、不上传 GitHub 等(本项目永远不需要发布到应用商店或更新服务器);
- 若只需便携版(例如 NSIS 资源下载失败):

  ```bash
  npx electron-builder --win portable --x64 --publish never
  ```

- SmartScreen 提示:未购买代码签名证书时,Windows 会提示"未知发布者",属正常现象;如需消除需自购证书并在 `build.win` 段配置签名。

## 3. macOS 版

**必须在 macOS 机器上执行**(交叉打包 dmg 不可行):

```bash
npm install && npm run build
npm run dist:mac -- --publish never
```

产物:`release/Encipherer-1.0.0.dmg`(拖入 Applications 安装)与 `Encipherer-1.0.0-mac.zip`。

前置条件:

- macOS 10.15+,Xcode Command Line Tools(`xcode-select --install`);
- **未做开发者签名时**,用户首次打开需右键 →「打开」,或在「系统设置 → 隐私与安全性」里点「仍要打开」(Gatekeeper);
- 正式分发建议购买 Apple Developer 账号,在 `build.mac` 段配置 `identity` 签名 + `notarize` 公证,否则用户会看到"已损坏"提示(可 `xattr -cr` 清除)。

## 4. Linux 版

建议在**对应发行版/容器**中执行(deb 的依赖元数据按构建环境生成):

```bash
npm install && npm run build
npm run dist:linux -- --publish never
```

产物:`release/Encipherer-1.0.0.AppImage`(chmod +x 后直接运行)与 `encipherer_1.0.0_amd64.deb`。

前置条件:常见 64 位发行版即可,无需额外工具链;如遇 `fakeroot`/`dpkg` 相关报错,在 Debian/Ubuntu 系环境下构建。

## 5. 常见问题

- **首次打包卡在下载 / GitHub 连接超时**:electron-builder 默认从 GitHub 下载 Electron 二进制与 NSIS 等资源,网络不通时可换国内镜像(见下方 5.1);
- **报错缺少 `dist/Encipherer.html`**:桌面壳启动时强校验此文件,先 `npm run build`;
- **`Cannot create symbolic link ... 客户端没有所需的特权`**:解压 winCodeSign 资源包时,Windows 非管理员/未开开发者模式账户无法创建包内的 macOS 符号链接(见 5.2,与 Windows 打包本身无关,可安全跳过);
- **只想改版本号**:改 `package.json` 的 `version`,重新 `npm run build` + `dist:*`,产物文件名中的版本号随之更新;
- 缓存位置:`%LOCALAPPDATA%\electron-builder\Cache`,下载成功后下次打包离线可用。

### 5.1 网络不通 GitHub:镜像 + 本地 Electron zip(实测有效)

```bash
# ① NSIS / winCodeSign 资源走 npmmirror 镜像
export ELECTRON_BUILDER_BINARIES_MIRROR="https://npmmirror.com/mirrors/electron-builder-binaries/"

# ② Electron 运行时:优先复用本机已有的 zip(npm 安装 electron 时已下载到
#    %LOCALAPPDATA%\electron\Cache\<hash>\ 下),拷到平级目录并告诉 electron-builder:
mkdir -p "$LOCALAPPDATA/ec-electron-dist"
cp "$LOCALAPPDATA"/electron/Cache/*/electron-v33.4.11-win32-x64.zip "$LOCALAPPDATA/ec-electron-dist/"
npx electron-builder --win portable nsis --x64 --publish never \
  --config.electronDist="C:\Users\<你>\AppData\Local\ec-electron-dist"
```

(若无本地 zip,可加 `export ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"` 从镜像下载。)

### 5.2 winCodeSign 符号链接权限错误的 workaround

以管理员或开发者模式运行可根治;不方便提权时,手动把资源包解压到最终缓存位置即可跳过该步骤(那两个符号链接只用于在 Windows 上给 macOS 包签名,纯 Windows 打包用不到):

```bash
CD="$LOCALAPPDATA/electron-builder/Cache/winCodeSign"
mkdir -p winCodeSign-2.6.0
node_modules/7zip-bin/win/x64/7za.exe x -y -bd <任意一次失败留下的 *.7z> -o"$CD/winCodeSign-2.6.0"   # 退出码 2 可忽略
rm -rf "$CD"/*.7z "$CD"/[0-9]*        # 清掉临时目录,只留 winCodeSign-2.6.0
```

之后重新执行打包命令即可。

## 6. 分发建议

1. 内部分发优先给**单文件版**(2 MB,人人可用);经常使用且在意本地保存(最近工作区列表)的用户给**桌面版**;
2. 无论哪种形态,提醒最终用户:**工作区密码无法找回**,建议配合密码管理器;详见《使用指南》FAQ;
3. 任何形态都不联网,可在隔离网络中分发使用。
